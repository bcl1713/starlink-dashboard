# PoP evidence acceptance

Run from a clean committed feature worktree:

```sh
timeout --kill-after=10s 45m python3 tools/acceptance/pop-evidence/run.py \
  --candidate-sha "$(git rev-parse HEAD)" \
  --evidence-root /tmp/new-private-pop-evidence
```

The shared production owner builds the exact candidate through the production
Dockerfiles and retains image identities, source hashes, command process groups
and teardown receipts. The isolated project loads `fixture.py` as its startup
module; ordinary deployments continue to load `main:app`. This explicit fixture
injects synthetic public IP/GeoIP and aircraft telemetry dependencies into the
shipped status service and resolver. No operational lookup or mission is used.

A real browser reads status through production Nginx without response
interception. Evidence includes the Tokyo map marker at sourced catalog
coordinates despite contradictory provider GeoIP, Operator provenance and
uncertainty, internal backend metrics, and a CSV generated by the shipped
timeline exporter from an invented future segment. Controls cover failed GeoIP
with mapped identity, changed-IP failure, unmapped GeoIP labeling and stale
evidence. These checks demonstrate identity and presentation behavior, not
physical Starshield routing or handover accuracy. Browser contexts and the
task's private containers, networks, volumes, images and listeners are removed
on exit.

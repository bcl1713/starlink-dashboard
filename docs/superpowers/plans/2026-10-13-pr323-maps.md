# PR323 Customer Maps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve issue 326 by reproducing omitted real-input maps, repairing
supported canonical timing/geometry, and surfacing specific limits before
publication.

**Architecture:** Keep canonical route/timeline data immutable. A pure scene
eligibility function supplies both export inputs and final-review diagnostics;
local renderer pixels and map metadata prove the supported route/window result.

**Tech Stack:** Python 3.11, existing route projector and map-input builder,
pytest, the packaged local JavaScript renderer, and production browser/PDF
controls.

**Spec:**
[Approved design](../specs/2026-10-13-pr323-operator-and-export-repair.md).

## Global Constraints

- [Parent constraints](2026-10-13-pr323-repairs.md) apply, including PR323,
  immutable private artifacts, scoped resources, and exact-head acceptance.
- No source-date changes, synthetic replacement routes, timestamp padding,
  arbitrary anchor relocation, warning suppression, or blanket relaxed limits.
- The current route/scene capacity is 2000 points and 200 markers. If density is
  the proven predicate, simplify the display while preserving exact anchors; do
  not solve it solely by increasing capacity.

## Review Focus

- Two occurrences at the same position must retain different window identity
  (Task 1).
- Untimed interior geometry with a canonical supported projector must remain
  distinguishable from truly unlocatable timing (Tasks 1–2).
- UTC offsets, overnight legs, and source-minute AR boundaries must retain exact
  canonical start/end relationships (Tasks 1–2).
- A capacity/antipodal/ambiguous input must receive a specific review diagnosis,
  not an empty successful map or moved route (Task 2).
- A nonblank basemap without route/window pixels must fail rendered map
  acceptance, both offline and online (Task 3).

## Task 2: pure scene eligibility and the proven minimal repair

**Files:** Modify `backend/starlink-location/app/mission/exporter/map_inputs.py`
and `customer_document.py`; create `app/mission/planning/map_review.py`. Extend
`app/mission/planning/models.py`, `review.py`, and the tests from Task 1; add
`tests/planning/test_map_review.py`.

**Interfaces:** Define frozen
`MapInputDiagnostic(code: str, message: str, window_id: str | None)` and
`MapInputResult(scene: dict | None, diagnostics: tuple[MapInputDiagnostic, ...])`.
Expose this scene interface:

```text
prepare_map_input(
    snapshot_leg: LegSnapshot, projected_leg: BriefingLeg
) -> MapInputResult
```

Keep `build_map_input` as its existing tuple-return adapter for existing
callers. The final-review interface is:

```text
map_review.check_map_review(
    snapshot_leg, projected_leg
) -> tuple[PlanningError, ...]
```

It calls the same pure eligibility function; final review receives its codes
before publication. Existing evidence remains readable; diagnostic-code fields
are additive. Diagnostic codes are `route_missing`, `route_timing_missing`,
`route_timing_non_increasing`, `route_bounds_mismatch`,
`route_coordinates_invalid`, `route_antipodal_segment`, `route_point_limit`,
`route_marker_limit`, and `window_position_unavailable`. Preserve severity so an
unsupported-map limitation cannot be mistaken for an ignorable
display-normalization note.

Operator quick reference

Before writing: confirm mission, named leg/gap, original scope and UTC. Unknown occurrence times stay unknown. Planned time, actual occurrence and backend recorded time are different.

Calls and preparation

  1. Create call for a requirement. A scheduled call needs planned start UTC.
  2. Use Record completed call for an event that happened. Enter known actual times/precision; keep unknowns unknown.
  3. Expand timing/association details for duration, preparation lead, shift, coordinator and conference. Zero lead is valid.
  4. Edit call reschedules or changes status. Cancel/reinstate differs from remove/restore record visibility.
  5. Wait for the receipt; review Call history.

Call procedure

Conference and customer reports

  1. Create conference, then report Establish and Verify after real bridge operations/checks.
  2. Customer Joined records an independent interval. Select the correct call/conference and participant.
  3. Check Report joined now using backend UTC only for an intentional current join. Otherwise report known UTCs or leave unknown.
  4. Interrupt conference and Restore conference connection concern the bridge.
  5. Interrupt customer and Restore connection concern that customer; restoration creates a linked new interval.
  6. Customer Left reports departure. Close conference does not automatically remove connected customer reports.

These controls report actions; they do not provision, dial or test hardware. Multiple reported customers may overlap.

Bridge procedure · Customer procedure

Now, Next and predictions

  • Now: customers reported connected.
  • Next: future preparation; overdue work remains separate attention.
  • Inspect source freshness and current-leg alignment. Partial/unavailable coverage is not all-clear.
  • Unknown PoP/handover is not an outage. Assume Starshield available unless disabled or deliberately down.
  • Transition windows remain advisories. Apply the agreed full planning outage only where Starshield is sole usable transport, accounting for usable Ka or coordinated concurrency-only X fallback.

Estimates do not require an uncertainty acknowledgment before saving a plan.

Transport, issues and observations

  • Transport: intended, requested, applied and checked stages are independent. Applied-only is valid.
  • Report checks separately by service. A changed application invalidates an earlier check; add the replacement check.
  • Issues: describe, add update/follow-up, Monitor, Resolve, Reopen. Inspect clearing versus retaining follow-up.
  • Historical correction fixes an earlier message/report without replaying its lifecycle or routing action.
  • Capability dimensions are independent; they do not replace an issue or prove actual routing.
  • Notes/History: retain original scope, UTC precision and unresolved associations. Load all relevant pages and include removed records when auditing.

Overview and alerts

Shared switches affect all displays; recenter targets a selected local window. Verify actual rendering.

Presets include panel/map and weather visibility. Wind and temperature are exclusive. Provider settings, forecast level/horizon, ACKs, history window and camera stay separate.

Partial apply: review Confirmed / Unconfirmed, refresh and apply again. Legacy presets report weather excluded.

Simulation retains chosen panels with Unavailable measurements/history. Browser cues need supported foreground permission and actual delivery checks. Acknowledge the current occurrence.

Ground gap and original mission ZIP

  1. Record Between legs with both named leg references.
  2. Preview/start the return leg in Missions normally. Verify current-leg sources and the same journal.
  3. Use the existing mission Export workflow for its single ZIP. Verify preparation/download/cancel/failure state.
  4. Extract and open the original briefing PDF; check legs and printed time zone; check journal/history, telemetry and checksums.
  5. Import into the separate intended destination; verify its pre-existing journal is unchanged.

A ZIP download is not human PDF review. Mission import is not journal backup/restore.

Private guided mission

Use a separate nonproduction instance and an empty marked root. Help → Guided mission walkthrough uses the real controls.

Next: visits instructions. Back: does not undo writes. Skip: not Passed. Check current evidence: requires current backend facts. Human observations remain separate.

For lost receipt, check evidence while uncertain before exact retry, then check again.

Reset guide: local guide progress only. Reset mission: run the explicit local command, then open its printed successor address. Old pending commands stay bound to the old store.

Restart retains the journal; it does not reconstruct an expired replay frame. Use the existing backup/check/restore procedure with the correct root/mode/namespace and stop the writer before restore.
